API prices are yours to enter. Nothing is hardcoded here — published prices change monthly and any figure baked into this file would be wrong by the time you read it. Take the two numbers off the provider's pricing page for the model you would actually rent. The comparison covers tokens only: egress, rate-limit headroom and the fact that your data leaves the building are not priced.

Your score is the model's result on your graded examples — not a public benchmark. Speed auto-fills with a rough estimate from memory bandwidth; it is a shortlisting guess that can be wrong by half. Type a measured number over it as soon as you have one, and it will be marked as measured.

4 · Sharing the hardware

Everything sharing the box is assumed to run the same model on the same deployment. Cost is split by how much of the capacity each side actually consumes, so your share falls as the box fills up. If the other work needs a different model, it needs a different box and this will flatter you.

Estimated speeds assume the model is memory-bandwidth-bound during generation, which is the usual case, with batching gains that flatten as concurrency rises. VRAM figures cover weights plus roughly 20% runtime overhead and exclude the KV cache, which grows with concurrency and context length — so treat a model that only just fits as one that doesn't. Nothing here is a substitute for running the thing on your own box for an afternoon.
